This chapter describes the technical implementation of the multi-agent fruit harvesting simulation. The system is built using Mesa 3.0, a Python framework for agent-based modeling, and implements the BDI agent architecture with an improved communication protocol featuring directional information sharing, idle agent detection, and interference modeling.

\section{System Architecture Overview}

The simulation system comprises four main components:

\begin{enumerate}
    \item \textbf{Environment Model}: A $30 \times 30$ grid world with static fruit resources
    \item \textbf{BDI Agents}: Autonomous harvester agents with belief-desire-intention architecture
    \item \textbf{Communication Infrastructure}: Range-limited selective broadcasting protocol
    \item \textbf{Data Collection}: Comprehensive metrics tracking and batch execution framework
\end{enumerate}

\section{Environment Model Implementation}

\subsection{Grid Structure}

The environment is implemented using Mesa's \texttt{MultiGrid} class, which provides:

\begin{itemize}
    \item \textbf{Dimensions}: $30 \times 30$ cells (900 total cells)
    \item \textbf{Topology}: Non-toroidal (agents cannot wrap around edges)
    \item \textbf{Occupancy}: Multiple agents can occupy the same cell
    \item \textbf{Coordinate system}: Cartesian coordinates with $(0,0)$ at bottom-left
\end{itemize}

The \texttt{HarvestModel} class manages the simulation environment and inherits from Mesa's \texttt{Model} base class. Key initialization parameters include:

\begin{itemize}
    \item \texttt{width}, \texttt{height}: Grid dimensions (fixed at 30×30)
    \item \texttt{num\_agents}: Number of harvester agents ($N \in \{10, 20\}$)
    \item \texttt{fruit\_density}: Proportion of cells with fruit ($\rho \in \{0.15, 0.25\}$)
    \item \texttt{comm\_range}: Communication range ($r \in \{0, 2, 4, 6, 8\}$)
    \item \texttt{seed}: Random seed for reproducibility (0-19)
\end{itemize}

\subsection{Resource Initialization}

Fruit resources are placed randomly at initialization with each cell containing at most one fruit. For $\rho = 0.15$, approximately 135 fruits are placed; for $\rho = 0.25$, approximately 225 fruits are placed.

\section{BDI Agent Implementation}

\subsection{Agent State Representation}

The \texttt{HarvesterAgent} class implements the BDI architecture through explicit state variables:

\textbf{Beliefs} (represented as sets):
\begin{itemize}
    \item \texttt{discovered\_fruits}: Set of known fruit locations $B_i \subseteq \mathcal{G}$
    \item \texttt{empty\_cells}: Set of cells confirmed to have no available fruit (memory optimization)
    \item \texttt{visited\_cells}: Set of all positions visited (for coverage metric)
\end{itemize}

\textbf{Intentions} (represented as target selection):
\begin{itemize}
    \item \texttt{current\_target}: Selected fruit location $\tau_i \in B_i \cup \{\text{null}\}$
\end{itemize}

\textbf{Performance and state metrics}:
\begin{itemize}
    \item \texttt{harvested}: Total fruits collected by this agent
    \item \texttt{messages\_sent}: Messages sent in current step
    \item \texttt{messages\_received}: Cumulative messages received (lifetime counter)
    \item \texttt{travel\_distance}: Total movement steps (for efficiency analysis)
    \item \texttt{idle\_steps}: Steps without finding fruit (indicates need for help)
\end{itemize}

\subsection{Behavioral Cycle Implementation}

The agent's \texttt{step()} method implements three phases:

\begin{enumerate}
    \item \textbf{Move}: Priority-based movement strategy with hierarchical decision-making: (a) Check for fruit at current position; (b) Search for nearby fruit within radius 2; (c) Pursue communicated targets if valid; (d) Navigate to remembered fruit locations; (e) Explore using Levy Flight and density heatmap.

    \item \textbf{Harvest}: Collect fruit at current position, update beliefs by removing harvested fruit from memory, and mark cell as empty for future reference.

    \item \textbf{Communicate}: Share ranked fruit locations with idle agents within communication range, implementing directional information sharing and interference modeling for high ranges.
\end{enumerate}

\subsubsection{Phase 3: Communication}

The communication protocol implements directional information sharing with idle agent detection and interference modeling:

\begin{lstlisting}[language=Python, caption=Communication protocol]
def communicate(self):
    if not self.pos or self.model.comm_range == 0:
        return  # No communication in control condition

    available_fruits = self._get_ranked_fruits()
    if not available_fruits:
        return  # Nothing to share

    neighbors = self.model.grid.get_neighbors(
        self.pos, moore=True, include_center=False,
        radius=self.model.comm_range)
    agent_neighbors = [n for n in neighbors
                       if isinstance(n, HarvesterAgent)]

    idle_neighbors = []
    for n in agent_neighbors:
        if n.current_target:
            continue
        nearby = n._find_closest_fruit_nearby(search_radius=2)
        if nearby:
            continue
        if n.idle_steps >= 2:
            idle_neighbors.append(n)

    if not idle_neighbors:
        return

    # Interference model for high ranges
    if self.model.comm_range > 4:
        interference = 0.05 * (self.model.comm_range - 4)
        if random.random() < interference:
            return

    for i, neighbor in enumerate(idle_neighbors[:5]):
        fruit_index = i % len(available_fruits)
        neighbor.receive_message(available_fruits[fruit_index])
        self.messages_sent += 1

def receive_message(self, fruit_pos):
    self.messages_received += 1
    self.discovered_fruits.add(fruit_pos)
    if not self.current_target:
        self.current_target = fruit_pos
\end{lstlisting}

\textbf{Key implementation details}:

\begin{itemize}
    \item \textbf{Directional communication}: Only agents with valuable information (ranked fruits) share with idle agents, creating targeted information flow.

    \item \textbf{Idle agent detection}: Agents are considered idle if they have no target, no nearby fruit, and have been idle for 2+ steps.

    \item \textbf{Distributed target assignment}: Different fruits are assigned to different agents to reduce herding and target contention.

    \item \textbf{Interference model}: High communication ranges ($r > 4$) experience message loss due to congestion, with loss probability increasing with range.

    \item \textbf{Range enforcement}: Mesa's \texttt{get\_neighbors()} with \texttt{radius} parameter automatically filters agents by Chebyshev distance.
\end{itemize}

\section{Communication Range and Interference Model}

\subsection{Chebyshev Distance Implementation}

Communication range is enforced using Chebyshev distance (also known as $L_\infty$ metric or chessboard distance):

\begin{equation}
d_{\infty}(p_1, p_2) = \max(|x_1 - x_2|, |y_1 - y_2|)
\end{equation}

\begin{lstlisting}[language=Python, caption=Chebyshev distance calculation]
def chebyshev_distance(pos1, pos2):
    return max(abs(pos1[0] - pos2[0]), abs(pos1[1] - pos2[1]))
\end{lstlisting}

This metric is implemented efficiently in Mesa's \texttt{get\_neighbors()} method with \texttt{moore=True} and a specified \texttt{radius}. For a given communication range $r$, an agent can communicate with all agents in a square neighborhood of size $(2r+1) \times (2r+1)$ centered at its position.

\subsection{Interference Model for High Communication Ranges}

Experimental results reveal that communication ranges $r > 4$ exhibit diminishing returns and reduced efficiency. This phenomenon is modeled as \emph{coordination interference}, where excessive information sharing creates overhead without proportional benefits.

\textbf{Interference mechanisms}:

\begin{enumerate}
    \item \textbf{Information redundancy}: At high ranges, agents receive many duplicate messages about the same fruit locations, providing no new information while consuming processing resources.

    \item \textbf{Stale information propagation}: Fruit locations are broadcast widely, but by the time distant agents receive the information and travel to the location, the fruit may already be harvested.

    \item \textbf{Target contention}: Multiple agents may select the same distant fruit as a target based on broadcast information, leading to redundant travel and wasted effort when only one agent can harvest it.

    \item \textbf{Exploration suppression}: When agents have many known targets from communication, they spend less time exploring new areas, potentially missing nearby undiscovered resources.
\end{enumerate}

\textbf{Quantitative interference model}:

The efficiency degradation at high ranges can be modeled as:

\begin{equation}
E(r) = \begin{cases}
E_{\text{max}} \cdot \frac{r}{r_{\text{opt}}} & \text{if } r \le r_{\text{opt}} \\
E_{\text{max}} \cdot \frac{r_{\text{opt}}}{r} \cdot e^{-\alpha(r - r_{\text{opt}})} & \text{if } r > r_{\text{opt}}
\end{cases}
\end{equation}

where $E_{\text{max}}$ is the maximum efficiency, $r_{\text{opt}} = 2$ is the optimal range, and $\alpha$ is an interference coefficient. This model captures the initial linear increase in efficiency up to $r_{\text{opt}}$, followed by exponential decay due to interference effects.

Empirical data shows:
\begin{itemize}
    \item At $r=2$: $E = 912.5$ (optimal)
    \item At $r=4$: $E = 255.9$ (72\% reduction)
    \item At $r=6$: $E = 150.0$ (84\% reduction)
    \item At $r=8$: $E = 102.3$ (89\% reduction)
\end{itemize}

This dramatic efficiency drop demonstrates that communication range optimization is critical for system performance.

\section{Data Collection and Metrics}

\subsection{Mesa DataCollector Integration}

The simulation uses Mesa's \texttt{DataCollector} class to track metrics at each time step:

\begin{lstlisting}[language=Python, caption=DataCollector configuration]
self.datacollector = DataCollector(
    model_reporters={
        "Total Yield": lambda m: sum(a.harvested for a in m.agents
                                     if isinstance(a, HarvesterAgent)),
        "Messages": lambda m: sum(a.messages_sent for a in m.agents
                                  if isinstance(a, HarvesterAgent)),
        "Remaining Fruit": lambda m: sum(1 for a in m.agents
                                         if isinstance(a, Fruit)
                                         and a.available),
        "Efficiency": lambda m: self._calculate_efficiency()
    }
)
\end{lstlisting}

\subsection{Collected Metrics}

\textbf{Primary performance metrics}:
\begin{itemize}
    \item \textbf{Total yield}: Cumulative fruit harvested by all agents
    \item \textbf{Remaining fruit}: Unharvested fruit at episode end
\end{itemize}

\textbf{Communication metrics}:
\begin{itemize}
    \item \textbf{Messages sent}: Total messages transmitted during episode
    \item \textbf{Messages per step}: Average communication overhead per time step
\end{itemize}

\textbf{Efficiency metrics}:
\begin{itemize}
    \item \textbf{Communication efficiency}: $E = Y / M$ (yield per message)
    \item \textbf{Normalized efficiency}: $(Y - Y_0) / M$ (improvement per message)
\end{itemize}

\section{Batch Execution Framework}

\subsection{Experimental Runner}

The batch experiment runner automates the 500 simulation runs (5 ranges × 100 replications):

\begin{lstlisting}[language=Python, caption=Batch execution framework]
def run_experiments():
    ranges = [0, 2, 4, 6, 8]
    team_sizes = [10, 20]
    densities = [0.15, 0.25]
    seeds = range(20)

    results = []
    for r in ranges:
        for n in team_sizes:
            for rho in densities:
                for seed in seeds:
                    model = HarvestModel(
                        width=30, height=30,
                        num_agents=n,
                        fruit_density=rho,
                        comm_range=r,
                        seed=seed
                    )
                    model.run_model(steps=500)
                    results.append(collect_metrics(model))

    save_results(results, "experimental_results.csv")
\end{lstlisting}
